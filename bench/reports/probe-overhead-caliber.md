# probe 开销口径问题：为什么「1.35x / 1.5x」不是一个可比的数

> 版本：**v1.0** · 日期：2026-10-06 · HEAD `8eb2b89` · 状态：**已定位，待裁决**
> 取数脚本：`bench/profiler-overhead/overhead_lab.py`（`--big` / `--decomp` / `--rounds`）
> 起因：跑 A2 立项实验时顺带发现 Gate C 的红线数（官方 harness）在同一台机器上连跑两次是 **1.53x FAIL / 1.44x PASS**

## 1. 结论

**探针开销不是一个数，是一个随「负载形状」摆动的函数。** 同一份 `monitor.py`、同一台机器、同一时点实测：

| 负载形状 | 单轮工作量 | 每函数次数 vs 静音阈值(200) | plain | V0 probe | **ratio** | cProfile | 其比率 |
|---|---|---|---|---|---|---|---|
| **S1 小工 × 高次** | 小 | 2000 ＞ 200（**静音触发**） | 36.3 ms | 57.3 ms | **1.58x** | 174.4 ms | 4.80x |
| **S2 重工 × 低次** | 大 | 150 ＜ 200（不触发） | 36.8 ms | 60.0 ms | **1.63x** | 197.0 ms | 5.36x |
| **S3 重工 × 高次** | 大 | 2000 ＞ 200（触发） | 503.3 ms | 589.5 ms | **1.17x** | 2664.8 ms | 5.29x |
| **S4 小工 × 高次、取消静音** | 小 | 不静音 | 36.5 ms | 90.6 ms | **2.48x** | — | — |
| S5 小工 × 低次 | 小 | — | 3.5 ms | 15.8 ms | ~4.6x ⚠ | 13.3 ms | 3.85x |

⚠ S5 的基准只有 3.5 ms，**测量噪声已压过信号**（同表出现 `V4 stack only = 0.77x` 这类物理上不可能的值），**不可用**——记录在此是为了防止下一个人再去用短负载测这个东西。

**跨形状摆动 1.17x ~ 2.48x（约 2 倍），叠加同形状跨 run 的 ±0.1x 抖动。** 历史上记的单一数字 1.35x，极可能是某次安静机器上的 S1 类读数；它既不代表最坏情形，也无法跨会话复现。

## 2. 归因（S4 口径下的成本拆解，`--decomp`）

| 形态 | min(ms) | ratio | 差额归因 |
|---|---|---|---|
| D1 full（现状行为，取消静音以隔离 mute 影响） | 90.6 | 2.48x | 基准 |
| D2 再关掉类型观测（`max_type_obs_per_site=0`） | 80.9 | 2.22x | **类型观测（compact/shape）≈ 0.26x** |
| D3 禁止「项目函数活跃 → 重开发现窗口」 | 76.3 | 2.09x | **全局 PY_START 常驻 ≈ 0.39x** |

两个最大的具体来源：

- `max_calls_per_func=200` 的**静音节流**：这是 S1(1.58x) 与 S4(2.48x) 的全部差异——**近 1x 的开销是被"调用过多后不再观测"这条节流规则藏起来的**。真实代码里每个函数的调用次数通常远低于 200，节流不会触发，用户实际感受更接近 S4。
- 「项目函数再度活跃 → 重开发现窗口」（`_on_start` 非窗口分支）：只要有项目函数在活动，全局 `PY_START` 就**全程常驻**，连库函数也派发回调。

## 3. 由此产生的三条口径纪律

1. **不得报单一倍率**。任何探针开销结论必须写明「哪个负载形状」，建议固定用 S1~S3 三形状报全。
2. **一次性装配成本（`Monitor` 构造 / `start()` / `stop()`）不得计入倍率**，作为常量另列——这与 A2 实验第一版踩的坑同源（当时得到假值 3.05x）。
3. **优先用「同批 run 内的 cProfile 对照」做归一化**。实测 cProfile 的比率跨形状稳定（4.80 / 5.36 / 5.29），而我们的比率随形状摆动；同一会话内取比值可抵掉机器状态差异。

## 4. 待裁决 —— ✅ 已裁决（2026-10-07）

① **裁决：否。** Gate C 维持**单形状官方 harness**（S1 同源，`bench_probe.ps1`），**不改多形状矩阵**——避免"今天即 FAIL"的口径切换引发误判为回归；三条口径纪律（§3）作为文档标注落实，进程内精测（reps ≥7，`overhead_lab.py`）为判定 0.1x 级差异的可信口径。
② **裁决：否。** 不只锁 S2。S1/S2/S3 三形状数据保留在本报告作参考基线，不进门禁。
③ **裁决：不启动 baseline 优化。** 两个杠杆（全局 `PY_START` 常驻 ≈0.39x、类型观测 ≈0.26x）都直接换取采集完整度——属功能取舍，不是能白拿的空间。A2 照现状推进（默认路径逐字不动即不恶化）。

## 5. ✅ 已落地：修掉「hits 被静音钳在 200」（2026-10-07）

现象：3 个真实项目的 trace 里 `hits` 的 max 恒为 200。根因是 `_mute()` 清掉了该 code 的**全部**局部事件——省开销的同时把 hits 一起停了，于是 `functions.hits ≤ max_calls_per_func`，热点榜与未来 Profiler 的 Top-N 到上限就分不出高下。

改法：**静音只清 `PY_RETURN`、保留 `PY_START`**，被静音函数走「只 `add_hit` 即返回」的分支（`_count_hit_only`）。省下的返回回调与 `compact_type` 成本，正好抵消继续派发的成本。

| 形态 | 改动前（hits 封顶） | 改动后（hits 无上限） |
|---|---|---|
| S1 小工 × 高次 | 1.56x | **1.56x**（`hits_max` 200 → 1999） |
| S3 重工 × 高次 | 1.08x | **1.10x** |
| E1（关类型观测，仅成本下界） | — | 1.40x |

⚠ **实现细节决定成败**：第一版把静音判断放在 `_maybe_close_window()` 之后，实测涨到 **1.71x**（每次派发多付一次 `perf_counter` + 一次函数调用，而 `_active > 0` 时窗口根本关不掉，这笔开销纯属白付）；把 `if code in self._muted` 提到 `_on_start` 最前面后回到 **1.56x**。

- 触发静音的那次调用也要计数，否则每次静音吞掉 1 次 hits（单测先抓到 `hits == 9` 而非 10）。
- 单测 `probe/tests/test_monitor.py::test_mute_after_limit` 已改为新语义（hits 无上限 + 类型观测仍节流）。
- 端到端核验 `bench/profiler-overhead/check_hits_e2e.py`（CLI run → 落库 → 回读）：1000 次调用 → `hits=1000`、`arg_obs` 仍 ≤ 200。
- 官方 harness 改动后连跑两次 **1.53x / 1.27x**，与改动前的 1.44~1.53x 属同一抖动带——**官方 harness 单次读数无法判定 0.1x 级差异**，进程内精测（reps ≥7）才是可信口径。
