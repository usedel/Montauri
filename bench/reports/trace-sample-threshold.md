# P0-2 第二格：样本量门槛口径裁决与收口

> 版本：**v1.0** · 日期：2026-10-07 · HEAD `8eb2b89`（工作区含 A2 立项产物）
> 上级：`docs/improvement_and_roadmap_report.md` §2 P0-2 第二格
> 数据：`bench/reports/trace-stats-cumulative.md`（3 个真实项目 / 7 次运行）

## 1. 裁决

> **「跨 ≥2~3 个真实项目累计 ≥1000 条观测」中的「条」= `functions` 表的函数观测数。**

即 `trace_stats.py` 汇总里的「函数观测数」，**不是**参数/返回/异常观测的合计。

## 2. 为什么是它（三条，逐条对齐这条门槛服务的对象）

| 门槛要支撑的决策 | 依赖的统计量 | 粒度 | 是否函数级 |
|---|---|---|---|
| `STALE_HITS_DIVISOR`（stale 降权系数） | stale 占比、hits 分布 | 每函数一行（`functions.hits` / `functions.stale`） | ✅ 函数级 |
| trace 库保留窗口（条数上限） | 每条观测平均字节 | 脚本按「函数观测数」反推 | ✅ 函数级 |
| 「观测是否够密以支撑排序」 | 覆盖率 = 有运行记录的函数 / 项目 def 总数 | 函数 | ✅ 函数级 |

反向理由：类型观测（参数/返回）是**按 (fid, 参数位, 类型标签) 去重聚合**的——同一个函数跑一万次，类型观测也不增加几条（还有 `max_type_obs_per_site=100` 的饱和上限）。用它的合计数当"样本量"，会把「一个函数被反复调用」误算成「样本更充分」，正好与该门槛要防的偏差同向。

**故：函数观测 497 < 1000，门槛未达。** 类型观测合计 1032 仅作参考数，不作达标依据。

## 4. 未达标的处置（收口）

1. **不再为凑数专门采样。** 本机可用采样源已确认触顶：`d:\aipro` 下 19 个目录里仅 3 个可离线运行（其余需联网 / API key / 无测试）；`D:\PycharmProjects` 下 8 个项目**无一可用**——可离线的 3 个（`mmbml` / `coral` / `smbter`）venv 全部指向已删除的 `D:\Python38`（3.8），既跑不起来，也低于 `sys.monitoring` 要求的 3.12，其余全是联网爬虫类。
2. **改为日常累积**：用 IDE 运行 / 调试脚本时 `run_env.rs` 已自动注入探针（`OPENCHARM_PROBE_AUTOSTART=1`），trace 自然落真实数据根，零额外操作。
3. **复核触发条件**（满足任一即重跑一次 `trace_stats.py` 并更新本文件）：① 日常使用累计后想看参数是否可定；② 新增一个 Python ≥3.12 且可离线运行的项目；③ 报告版本评审。

## 5. 参数状态（一律"建议值"，不是已定）

| 参数 | 现状 | 本轮裁决 |
|---|---|---|
| `STALE_HITS_DIVISOR` | 2 | **维持 2**——函数观测未达 1000，且 **stale 真实证据仍为 0**：3 个项目 / 7 次运行期间从未编辑过文件，唯一 stale 证据仍是 2026-10-03 那次合成实验（30%） |
| 保留窗口 | 建议 ≤ 11,309 条或 8 MB | **维持建议值**（按当前 742 B/条反推） |
| `max_calls_per_func` | 200 | ✅ **已修（2026-10-07）**：静音改为只清 `PY_RETURN`、保留 `PY_START`，hits 不再被钳在 200（实测 1000 次调用 → `hits=1000`，开销与改动前持平：S1 1.56x→1.56x、S3 1.08x→1.10x）。实现细节与回归数据见 `bench/reports/probe-overhead-caliber.md` §5 |
